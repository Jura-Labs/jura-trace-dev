**Target: Wednesday 30 September 2026.**
**Decision record: `~/jura-brain/decisions/2026-09-03-trace-v110-release.md`.**
**Scope note and evidence: `~/jura-brain/inbox/2026-09-03-trace-v101-scope.md`.**

Written 3 September 2026 by the Trace instance, from four Fable reviews
(project-manager, legal, devops, ml-data-scientist) plus three more on
adoption (persona-testing, content-authenticity-expert, devops), and from
first-hand checks of the code and the live systems.

## What this release is

v1.0.0 shipped on 18 June 2026 and nothing has been committed since 19
June. In that time nobody has received an update, because the updater has
never worked; nothing has been tested by CI, because it only runs on pull
requests and has been red since April; and nothing could have told us about
a new vulnerability, because all three detection routes are silent.

So this is a repair release. It is not a small one: with the accessibility
and honesty fixes it carries roughly fifteen user-visible changes, which is
why it is v1.1.0 and not v1.0.1. The single measure of success is that a
person running v1.0.0 receives it without being told to.

### Explicitly out, and why

Watermarking, to v1.2.0: the algorithm records 0% survival at JPEG Q70,
crop 20%, resize 75% and screenshot, which are the transformations the
feature exists to survive. The CLI, to v1.2.0: highest ceiling of anything
reviewed, but gated on BL-API-001, because the documented headless API does
not exist. Windows PyInstaller `--onedir`, to v1.2.0: it beats every
adoption lever for retention, since Windows is 64% of users and `--onefile`
re-extracts for 90 to 200 seconds on every cold start, but it touches the
installer and signing. Also out: Conformant signing, ADJPEG, PRNU, SynthID,
model download-on-first-run, quantisation, Flathub, Snap, an apt repo.

## Capacity, stated before the plan

At three and a half days a week on Trace, there are about **14 to 15
working days** between now and the target. The committed scope, meaning the
floor plus Tier 1 and 2, the export, the PDF minimum, W37-1 and the release
week, is about **15 to 16 days**.

That is zero slack, and it is only honest with Tier 3 and three of the five
growth levers pre-cut, which the plan below does. If ROOTED or Denmark
takes more than one unplanned day, the export is the first casualty by
design.

## Sequence

**Thursday 4 to Friday 5 September, 2 days. Infrastructure floor.**
Worker fix (F1 to F3), deployed and verified against the v1.0.0 assets. CI
push trigger, ruff pinned, OSV flag removed and made to fail on a missing
SARIF. Dependabot cap raised, two stale PRs closed. **And on day one, run
`cargo test` and the sidecar pytest suite locally**, to find four months of
rot now rather than in the final week.

**Week of 7 to 11 September, ~3.5 days. Publication and CI green.**
**W37-1 lands this week and that is not negotiable**: source public, CI
green on three platforms, Codeberg retired. Everything downstream depends
on knowing the final repository: the in-app source link, where `latest.json`
lives, the release asset names. Then clear the 67 ruff findings, get
`cargo test` and pytest green, run `npm audit fix`, merge the safe bumps,
and do the small Tier 1 items (T1.1, T1.3, T1.4).

**Week of 14 to 18 September, ~3.5 days. Features.**
The startup update check first (T1.2), because without it the manifest fix
reaches nobody. Then the Verification Record Export, **timeboxed to two
days**. Then the PDF minimum, falling back to gating drag-and-drop only if
squeezed. The checkpoint falls on the Wednesday.

**Week of 21 to 25 September, ~3.5 days. Tier 2, AppImage, freeze.**
The Tier 2 batch. Restore the Linux AppImage. **Code freeze on Friday 25
September**, with the local macOS build cut from a clean working tree,
remembering the cargo macro-cache wipe. Dry-run the update path against a
release candidate the same day, so the final week is confirmation and not
discovery.

**Monday 28 to Wednesday 30 September, ~2.5 days. Release gate.**
End-to-end update from the public v1.0.0 on macOS, Windows and Linux, in
the UTM and OrbStack VMs. Nothing ships if any platform fails. Release
notes, the re-download notice drafted in Brevo, the README correction
staged. Then on the Wednesday: tag, publish the assets and `latest.json`,
deploy the worker, send the notice, merge the README correction.

## Critical path

Worker fix, then W37-1, then the startup update check, then the local macOS
build, then the three-platform end-to-end update test, then release.

The three things most likely to slip it:

1. **Test rot since 30 April**, of unknown size. This is why both suites run
   on day one.
2. **The three-platform update gate**, especially Linux with a
   freshly restored AppImage in the matrix.
3. **ROOTED pilot interruptions** landing in the middle week.

## Go/no-go, Wednesday 17 September

**Must be true:** the public repo is live with three-platform CI green;
the worker fix is deployed and its completeness assertion passing; the
ruff, OSV, dependabot and npm floor is complete; the startup update check
is merged.

**If not, cut in this order** until the floor fits: Tier 3, then the CLIP
precompute, then the Verification Record Export, then full PDF mode
(keeping the drag-and-drop gate), then the AppImage.

The floor, the update check and the end-to-end gate are never cut. Since
the date is fixed by decision, scope absorbs everything.

## Growth levers, decided

- **In:** the W37-1 publication package, which is effectively mandatory
  anyway, and the Linux AppImage, because users are stranded and the
  manifest generator already expects it.
- **In only if the fourth week has slack, otherwise v1.1.1:** the CLIP text
  precompute and the pyarrow exclusion. 356 MB is real, but touching model
  packaging days before a freeze is how releases break. Monday 21
  September or not at all.
- **Out:** winget, the Homebrew tap and AUR. None of them is coupled to the
  release date. Batch all three into a v1.1.1 "channels" week in October,
  where they will also benefit from the repo being public and having some
  history.

## What ships, for the release notes

- **Auto-update works.** A startup update check, a corrected update
  manifest, and Linux x86_64 restored.
- **Verification Record Export**, signed and informational, which does not
  determine, certify or guarantee compliance.
- **PDF document mode**, read-only Content Credentials for PDFs, or
  corrected PDF handling if the checkpoint cuts it.
- **Clarity**: a reliance note near the verdict, N-of-M labelling on
  degraded results, a plain-English gloss on the untrusted-credential
  banner, a sidecar cold-start indicator.
- **Security**: the dompurify fix, three audit follow-ups, a dependency
  refresh, and hardened CI and supply-chain scanning.
- **Source now on GitHub**, with the in-app link updated and Codeberg
  retired.
- **Action for existing users**: re-download, because v1.0.0 cannot
  self-update.

That last line is the release note that matters, and it is why the
re-download notice is part of the release rather than a follow-up.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Test rot since 30 April blocks CI going green | Run both suites locally on 4 September. Anything red takes the first two weeks' budget before feature work starts |
| The update test fails on one platform in the final week, with no runway | Dry-run the update path against a release candidate on Friday 25 September, so the last week confirms rather than discovers |
| ROOTED or Denmark compresses the middle week | This is what the 17 September checkpoint is for. The export and full PDF mode are the designated shock absorbers, and cutting them keeps the date without touching the floor |
