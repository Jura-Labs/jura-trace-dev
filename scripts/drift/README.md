# Drift harness

Checks whether a dependency bump changes what the sidecar computes, image by
image and number by number, before the bump is merged. It was written for
the 8 September 2026 numpy, scipy, opencv and scikit-learn test and is
described in `docs/planning/v1.2.0-dependency-debt.md` section 8.

It compares two or more Python environments that differ only in their
pins, running the sidecar code from **this checkout** (so a run from a
worktree tests that worktree) against a fixed golden set of 84 images:
42 PNG and JPEG originals from the corpus, and 42 AVIF, HEIC and WebP
variants generated from corpus originals, across four classes.

## What is and is not in the repository

| In the repository | Outside it |
|---|---|
| The probes, the runners, `envs/*.txt` (the pinned environments) | The corpus |
| `golden_manifest.json`: every golden image by id, class, format, size and SHA-256, and for each variant the size and SHA-256 of its original | Anything with a corpus path in it: the working golden set, the variants, results, virtual environments |

The manifest has no paths because the corpus folder and file names are not
published. `resolve_golden.py` finds each original in your copy of the
corpus by size and hash.

## Running it

```sh
export JURA_DRIFT_CORPUS="/Volumes/Samsung USB/Training Data/corpus"
export JURA_DRIFT_WORK=~/.cache/jura-drift        # the default

python3 resolve_golden.py resolve                 # manifest + corpus -> working set
./build_envs.sh baseline candidate                # uv; seconds with a warm cache
$JURA_DRIFT_WORK/envs/baseline/bin/python gen_variants.py   # must print "all 84 golden files match"
./run_all.sh                                      # five probes in baseline and candidate
$JURA_DRIFT_WORK/envs/baseline/bin/python compare.py         # writes $JURA_DRIFT_WORK/comparison.json
```

For a single-variable attribution run (onnxruntime or regex, say), add
`envs/<name>_only.txt`, a copy of `baseline.txt` with one pin changed, build
it with `./build_envs.sh <name>_only`, and run the probes that touch that
package with its Python. `run_attrib.sh` is the 8 September example.
